# 🔁 Release retrospective — v1.12.0 (the first one; baseline for all future retros)

**Window:** v1.11.1 → v1.12.0, plus #282/#283 merged just after the tag and #284/#285 still open.
**Corpus read in full:** 12 merged PRs, 2 open, **30 posted review verdicts** (counted by this directory's convention: review bodies containing APPROVE or REQUEST CHANGES, across the 12 merged PRs), 7 issue bodies + close-the-loop comments, and the Project 3 telemetry. No previous prediction to check — this establishes the baseline.

## 1. Acceptance criteria

**One AC was unachievable as written** (#277: "mutation refresh→re-select fails at least one test" — measured `880 passed, 0 failed`; `expire_on_commit=False` plus the shared-session fixture makes the two spellings indistinguishable). The same shape had been handled *correctly* 14 hours earlier in #240, where the author documented the equivalence instead of writing a pin that cannot fail — and nobody carried that forward.

**Six of eight feature PRs shipped with a silently-unmet AC**, caught only in review: #284 (button latch absent entirely), #258 (AC5 blocked on a dependency that had already merged), #256 (the flagship one-command flow produced no admin account), #257 (four real-identity strings still rendering), #255 (SSR meta regressed), #261 (README claimed coverage no test asserted).

**`Closes #NN` against an unmet AC: 5 occurrences in 4 PRs** — all caught by the reviewer, none reached main. That is five blocker-level catches for something one `gh issue view` would have shown.

**What makes an AC good here:** a command with its expected output (#260, #235 — both got independently replayed); the command must be *right* (#66's case-SENSITIVE grep structurally could not see the lowercase occurrences review found); name the layer on any criterion that crosses one (#279 mixed frontend and backend in one list and only the backend half shipped); and never demand a mutation-pin without first confirming the two states are observably different.

## 2. Issue quality

**Grounding is genuinely good** — #65 carries ~20 `path:line` citations and the reviewer flagged **zero** as wrong; same for #66 and #69. Not one finding in 34 verdicts says "the issue cited something that isn't there."

Two real defects, neither of them grounding: **line numbers drift** behind a merge train (#277 cited `:302`, implementation found `:365`), and **the diagnosis changed on first contact twice** (#277's "latent bug" was measured as a no-op; #258's "blocked on #65" was false — #65 had already merged).

## 3. Code quality — defect classes

My four guesses were right; the retro found three more and counted them:

| Class | Count | PRs |
|---|---|---|
| **A. Claim asserted rather than measured** | ~30 findings, **9 blockers** | **14 of 14** |
| **B. Fake-green tests / gates that don't gate** | 24 findings | 10 |
| **C. Guarantee asserted at a layer that can't enforce it** | 3 blockers + 2 majors | 3 |
| **D. Content lost across a rebase, unverified** | 6 | 6 |
| **E. A mechanical guard whose justification is false** | 5 findings — **still unfixed** | 4 reviews + #276 |
| **F. Maintained doc registries go stale** | 6 | 5 |
| **G. `Closes` with an unmet AC** | 5 | 4 |

**Class A did not spare a single PR.** Numbers quoted from memory or a stale head, repeatedly: 15→18, 43/320→44/332, 13→12, "0 stale hits"→2 (three times in one PR's life), "2280 samples / 0 errors"→**2160 with 20 real connection failures**, and a "grep returns nothing" that returned **41 hits**.

**Class B's signature:** the fix that closed the *previous round's* blocker is the one nobody mutation-checks — that was a blocker **five times** (#240, #255, #256, #261, #284), each in a PR whose other tests *were* mutation-checked.

**Class C is the most dangerous and the least visible:** the unit tier structurally cannot see a race, because `conftest.py` yields one shared session to every request. "880 passed" said nothing about concurrency while two concurrent promotes created two permanent cards.

## 4. Review actions

**Reviewers verified by running, essentially always** — four full prod-topology boots on published images, mutation of *served JS bundles*, an `asyncio.Barrier` to reproduce a race, a migration run against a prod-like DB with pre-existing duplicates, and a test suite run under Linux `mawk` inside a container to check a portability risk.

**What repeated, and therefore belongs author-side:** "your fix has no failing-first test" (5 blockers) · "that number doesn't reproduce" (14/14 PRs) · "you `Closes` an unmet AC" (5) · "a gate you rely on doesn't gate" (5 PRs) · "you have no evidence for the E2E/integration layer" (**12 of 12** merged PRs).

**One process defect on my side:** #282 was approved at round 2, then I added six more tests — reopening the review and costing rounds 3 and 4. The growth was substantively worth it (round 3 found a genuinely vacuous assertion), but **7% of all review passes existed because of post-approval scope growth**.

## 5. Cost

| | v1.12.0 |
|---|---|
| Verdicts posted | **30** |
| REQUEST CHANGES | **17** |
| Mean rounds / merged PR | **2.5** |
| Approved on round 1 | **2 / 12 (17%)** |
| Review passes existing only because of rework | **18 / 30 = 60%** |

**Rework is superlinear:** rounds 2+ cost **172.7k tokens on average vs 115.4k for a round 1** — and account for **75% of all measured review tokens** — because the reviewer re-verifies every prior finding. Meanwhile tool uses *collapse* (79→33→21), so later rounds aren't more investigation; they're more accumulated context.

**Telemetry correction found by the retro:** #235's 900k/300min/5 rounds is filed under v1.11.1, but PR #240 merged *after* that tag and its changelog rotated into v1.12.0. True v1.12.0 cost: **9.07M tokens / 28.1h / 28 rounds**. The `release` field was recording where work was *slated*, not where it *landed*.

## Changes being applied (PR incoming)

1. **NEW HOOK `pre-merge-gate.sh`** — denies `gh pr merge` when the latest verdict isn't an APPROVE, or when the body says `Closes #NN` against an issue with unticked criteria. Rule 13 is restated in six places as prose with **zero** mechanical enforcement; class G was a blocker four times.
2. **Delete the unconditional "`Closes #NN`" instruction** from both dev charters — it is the direct cause of class G.
3. **`issue-author` learns how to write an AC that can be met** — four rules, each earned this release.
4. **`pr-reviewer.md` says "rules 1–8"** while CLAUDE.md has 13 — it omits rule 12 and rule 13, the reviewer's own mandate.
5. **`backend-dev` gains the E2E/integration instruction it never had**, plus the round-N mutation rule.
6. **Playbook:** one clause added; **two duplicated rule restatements deleted** (−14 lines) — duplication is how the renumber drift happened.
7. **lessons §30** (assert the guarantee where it can be enforced; the shared-session fixture hides races) and **deletion of the drifted config map** in lessons-learned (it listed four of eight commands).
8. **`/prep-pr` gains re-measure-every-number and layer-evidence steps.**

**No ninth agent.** Three candidates were considered and rejected with reasons — the evidence asks for *enforcement of rules the existing eight already have*, not a new owner.

## 📌 Prediction (checkable at the v1.13 retro)

**Mean review rounds below 2.0** (baseline 2.5) with **≥40% approved on round 1** (baseline 17%); **zero blocker-level class-A findings** (baseline 9); **zero "fix has no failing-first test" blockers** (baseline 5).
